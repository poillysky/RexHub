## 一、项目概述

### 1.1 项目定位

本项目是一套面向个人使用的影视资源发现与在线播放平台。

- iOS App 提供影视浏览、资源搜索、资源选择和在线播放体验。
- NAS 自托管后端统一管理资源来源、元数据服务、插件、115 网盘授权、转存任务及字幕服务。

项目**不是** Emby、Plex、Jellyfin 类型的媒体服务器，也不是个人媒体库管理系统。

核心业务流程：

```text
影视发现 → 资源搜索 → 资源选择 → 115 转存 / 直接在线播放
```

两条主要播放路径：

1. **网盘在线**：资源转存至 115 → 获取转存状态 → 解析 115 播放地址 → App 播放器播放。
2. **在线播放**：获取来源提供的 HTTP/HTTPS 播放地址 → App 播放器直接播放。

项目以资源发现和获取为核心，不建设复杂的影视观看管理系统。

### 1.2 项目目标

- 提供现代化、接近原生 iOS 体验的影视浏览界面。
- 聚合多个资源来源，实现统一搜索。
- 以搜索准确性为第一原则，避免语义噪音污染。
- 支持影视详情与整季资源发现。
- 实现 115 网盘转存和在线播放一条龙流程。
- 支持 HTTP/HTTPS 资源直接在线播放。
- 建立独立字幕服务，支持多字幕来源。
- 通过插件扩展资源搜索、短剧、影视元数据和字幕能力。
- 所有核心业务由 NAS 后端统一管理。
- 尽量复用成熟的 Python 115 客户端能力，不重复开发已有功能。

### 1.3 非项目目标

明确不建设以下功能：

- 不做 Emby 式媒体库。
- 不做复杂的观影状态管理（未看 / 观看中 / 已看完）。
- 不做用户评价、评论和评分社区。
- 不做资源评论系统。
- 不做 iPhone 本地视频下载。
- 不做 iOS 文件管理器。
- 不做复杂的 BT 在线流媒体服务。
- 不做影视内容人工维护系统。
- 不做复杂的视频文件内容识别。
- 不重复开发 Python 115 客户端已有能力。

## 二、整体产品架构

### 2.1 系统组成

**A. iOS App** —— 负责用户交互和实际使用体验：

- 影视首页及栏目展示。
- 影视作品详情。
- 资源搜索与结果展示。
- 资源详情。
- 115 转存操作。
- 在线播放器。
- 字幕搜索与管理。
- 短剧浏览和播放。
- 115 网盘管理入口。
- 用户设置和私密模式。
- 收藏、搜索历史和播放历史。

**B. NAS 后端服务** —— 负责所有核心业务逻辑：

- 用户认证与权限。
- iOS API 与 Web 管理 API。
- 影视元数据聚合。
- 资源搜索调度。
- 搜索结果标准化。
- 资源去重与过滤。
- 缓存。
- 插件管理与执行。
- 115 账号授权管理。
- 115 转存及播放地址解析。
- 播放会话管理。
- 字幕搜索、下载、索引与存储。
- 搜索历史、收藏及播放历史。
- 后台任务执行。
- 配置持久化。

**C. Web 管理端** —— 负责后端服务和插件的管理：

- NAS 服务配置。
- 资源搜索来源管理。
- 插件管理。
- 元数据 Provider 管理。
- 字幕来源管理。
- 115 服务配置。
- 后端运行状态。
- 日志和错误诊断。
- 用户及权限管理（后续多用户能力）。

> 注意：首页布局和栏目设计由 iOS App 管理，Web 不负责提供首页可视化编辑器。

### 2.2 系统关系

```text
                  iOS App
                     │
                     │ HTTPS API
                     │
              NAS 后端服务
                     │
       ┌─────────────┼─────────────┐
       │             │             │
   影视元数据     资源搜索       字幕服务
   Provider       Adapters       Plugins
       │             │             │
       └─────────────┼─────────────┘
                     │
              统一业务数据层
                     │
       ┌─────────────┼─────────────┐
       │             │             │
    PostgreSQL    115 Python     插件系统
                  客户端
       │             │
       │          115 网盘
       │
    资源索引
              Web 管理端
                     │
                NAS API
```

### 2.3 数据流原则

- iOS 不直接管理各资源来源的授权凭证。
- iOS 不直接连接 PostgreSQL。
- iOS 不直接管理 Python 115 客户端。
- NAS 负责业务控制、数据标准化和任务执行。
- 视频数据尽可能由 iPhone 直接访问真实资源来源。
- NAS 不作为常规视频流代理，不承担大流量视频转发。
- 播放地址由 NAS 负责解析，播放流尽量由 iPhone 直接获取。

## 三、iOS App 信息架构

底部导航固定为四个入口：

1. 影视
2. 短剧
3. 网盘
4. 更多

### 3.1 影视

影视是 App 的核心入口，主要包括：

- 影视首页。
- 首页栏目配置。
- 影视作品详情。
- 电视剧和动漫剧集列表。
- 资源搜索。
- 资源详情。
- 网盘在线。
- 在线播放。
- 收藏入口。
- 私密模式。

**影视首页**

- 采用可配置的影视栏目海报墙。
- 数据不由人工维护，通过影视元数据 Provider 获取。
- 可接入的数据类型：热门电影、近期电影、热门电视剧、最近更新剧集、高分电影、动漫及其他可配置影视分类。
- 首页具体栏目和样式由 iOS App 管理。

**首页配置职责**

| 端 | 职责 |
| --- | --- |
| iOS | 创建和管理栏目、调整顺序、显示/隐藏、配置数据类型、筛选条件、展示数量、布局与卡片样式、管理首页展示效果 |
| NAS | 提供首页配置 API、保存 iOS 提交的配置、提供栏目所需影视数据、按配置请求元数据 Provider、提供配置同步与恢复 |
| Web | 不负责首页布局设计，不提供首页栏目编辑器；只负责元数据服务及其 API 配置 |

首页配置的扩展方向：栏目布局、横向/纵向展示、海报尺寸、卡片样式等可逐步开放，具体自定义程度在 UI 设计阶段最终确认。

### 3.2 影视全局搜索

- 顶部提供统一搜索入口，定位为**纯资源搜索**，不混合影视元数据搜索。
- 输入作品名后直接调用已启用的资源搜索来源。
- 搜索结果以紧凑资源列表展示。

单条资源建议展示：资源标题、来源名称、资源类型、文件大小、文件数量、更新时间、可用操作。

快捷操作：复制资源链接、115 转存、网盘在线、在线播放、查看详情。

- 资源搜索结果不要求关联影视作品 ID。
- 全局搜索与影视详情页搜索共用底层搜索调度、标准化资源模型和操作服务，但查询上下文不同。

### 3.3 影视作品详情页

点击首页影视海报进入作品详情页。

**基本信息**

- 海报、背景图、作品名称、原名和别名、上映年份、简介、演员信息、作品类型、评分及其他元数据（来源提供时）、影视元数据来源。
- 图片优先使用元数据来源提供的原始图片。
- 资源自身提供的封面、截图、预览图等也可以在资源详情页展示。
- 需要建立图片与影视作品、资源之间的关联关系，避免错误匹配。

**电影详情**

展示：作品元数据 → 资源搜索状态 → 多来源资源列表 → 资源操作入口。电影不展示季和剧集列表。

**电视剧和动漫详情**

展示：作品基本信息、季/季度选择、剧集列表、整季资源、单集资源入口。默认以整季资源为主要展示内容；用户选择具体剧集后，才单独搜索该集资源。

交互：

1. 点击剧集。
2. 当前详情页底部弹出资源面板。
3. 面板展示当前剧集的资源搜索结果。
4. 关闭面板后仍留在原详情页。
5. 点击资源进入独立资源详情页。

整季资源和单集资源应明确区分。

**文件与剧集识别**

纳入轻量级文件名识别能力（优先级较低），识别常见命名：`S01E01`、`S01E02`、`01x03`、`第01集`。

- 识别成功时标注对应季集。
- 识别失败时保留原始文件名。
- 不做复杂视频内容分析、人工校正或自动整理。

## 四、资源搜索系统

资源搜索是本项目最重要的核心业务之一。

### 4.1 设计原则

1. 搜索准确性优先。
2. 宁可少返回，也不使用大量无关结果填充列表。
3. 资源来源可以不同，不强制所有来源插件化。
4. 统一资源模型，但保留来源特色信息。
5. 多来源并发搜索。
6. 结果逐步返回。
7. 单来源失败不影响其他来源。
8. 支持缓存、去重、筛选和排序。

### 4.2 搜索来源分类

| 类型 | 说明 |
| --- | --- |
| A. 自托管 PostgreSQL 资源数据库 | 由后端原生 Adapter 连接：查询数据库、处理搜索条件、转换数据、返回标准资源对象 |
| B. 外部 Docker 搜索服务 | 如 CloudSaver、PanSou 等可通过 HTTP API 调用的服务，由 NAS 后端编写独立 Adapter，不强制插件化 |
| C. HTTP 统一接口插件 | 用于扩展其他资源来源，实现约定接口即可接入，无须修改核心业务代码 |

### 4.3 资源标准化模型

所有来源的搜索结果转换为统一资源模型：

| 字段 | 说明 |
| --- | --- |
| `resource_id` | 内部资源标识 |
| `title` | 资源标题 |
| `resource_type` | 资源类型 |
| `resource_url` | 原始资源链接 |
| `provider_id` | 来源标识 |
| `provider_name` | 来源名称 |
| `size` | 文件大小 |
| `file_count` | 文件数量 |
| `updated_at` | 来源更新时间 |
| `metadata` | 来源扩展数据 |
| `capabilities` | 支持的操作能力 |
| `artwork` | 资源图片信息 |
| `raw_data` | 原始来源数据 |

- 来源特色信息放入 `metadata` / `extension`。
- `capabilities` 描述资源支持的操作：`copy_link`、`transfer_115`、`direct_play`、`view_detail`、`file_list`。
- 不能因为统一模型而假设每个来源都具备相同能力。

### 4.4 搜索准确性与过滤

准确性是搜索系统的第一优先级。例如搜索「流浪地球」，不应仅因为标题包含关键词就返回「我的流浪地球之旅」等无关资源。

搜索应综合考虑：作品标准名称、原名、别名、译名、年份、季数、集数、作品 ID、资源标题中的版本信息。

- **严格匹配**：默认优先展示明确属于目标作品的资源，不能仅凭关键词包含关系认定资源相关。
- **相关结果**：续作、同系列、相似名称等结果默认过滤；提供「显示更多相关结果」入口，用户主动展开后才展示低置信度或关联作品，并明确标注关联类型。
  - 示例：搜索《流浪地球》（2019）时，《流浪地球 2》（2023）不进入默认结果，用户主动展开后才可查看续作。
- **搜索上下文**：
  - 全局搜索：以关键词精确匹配为主，不强制关联影视作品，避免语义相似但不相关的资源。
  - 影视详情搜索：使用已确定的作品信息约束搜索，结合作品 ID、年份、季数和集数，优先获取对应作品资源。
- 资源来源可能只提供标题和链接，不能假设所有来源都能返回真实影视内容；无法可靠判断时保留原始信息，不做错误的自动归类。

### 4.5 多来源并发搜索

- 同时请求多个已启用来源。
- 每个来源独立显示状态：等待中、搜索中、已完成、失败、已取消。
- 哪个来源先返回就先展示哪个来源的结果，不等待全部来源结束。
- 支持：取消全部搜索、单独取消某个来源、重新搜索失败来源、单独刷新某个来源、查看最终搜索状态。
- 取消搜索不清空已经返回的结果。
- 取消状态与失败状态必须区分。

### 4.6 搜索缓存

- 相同关键词优先展示缓存结果，并显示缓存时间。
- 不自动强制重新请求所有来源；用户手动刷新时才重新搜索。
- 支持单独刷新某个来源。
- 缓存有效期由后端统一配置。
- 缓存应区分搜索上下文和私密模式，避免错误复用。

### 4.7 资源去重

- 自动识别相同资源并合并展示。
- 磁力资源优先根据 InfoHash 去重。
- 网盘资源根据分享链接及相关标识去重。
- 其他资源根据可靠的来源标识判断。
- 无法可靠确认重复关系时，不强行合并。
- 合并后保留全部来源信息。

### 4.8 搜索结果排序

默认采用综合排序，准确性优先级高于其他因素。排序参考：

1. 作品匹配准确度。
2. 标准名称匹配程度。
3. 年份、季数、集数匹配程度。
4. 来源可信度及数据质量。
5. 更新时间。
6. 文件大小等辅助信息。

不允许仅因为标题关键词相似就提升排序。

### 4.9 筛选能力

第一阶段支持：来源筛选、资源类型筛选（来源提供时）、文件大小筛选（来源提供时）。

清晰度、视频编码、字幕语言、音轨语言**不作为**通用筛选条件；只有来源明确提供可靠数据时，才考虑启用相关筛选。

### 4.10 资源详情页

资源详情采用独立完整页面，不使用简单底部弹窗代替。

**基本信息**：完整资源名称、来源名称、资源类型、更新时间、文件大小、文件数量、原始资源链接。

**图片信息**：根据来源提供情况展示影视海报、资源封面、资源截图、预览图。

- 优先使用资源自身提供的图片。
- 资源没有图片时，可尝试通过可靠的影视元数据关联补充，但必须避免错误关联。

**文件列表**：只展示文件信息，不提供文件级操作。

- 展示：文件名、文件格式、文件大小、文件数量、总大小（来源提供时）。
- 不开发文件级播放、转存、重命名等复杂操作。

**来源扩展信息**：来源特色字段、分享信息、磁力哈希（适用时）、原始返回信息（可折叠）、来源更新时间。

**操作区域**：复制链接、115 转存、网盘在线、在线播放。

不做评论、用户评分和评价系统。

### 4.11 多磁力链接多选转存

只实现明确的业务场景：同一个影视作品或同一季资源组内，多条磁力链接允许多选转存。

- 功能：单选、全选、取消选择、一次提交多条磁力链接、展示转存结果。
- 不做跨影视作品的通用批量操作。
- 去重后仍存在多条独立磁力链接时，可以参与多选。

## 五、115 网盘系统

### 5.1 核心原则

- 115 网盘能力由 NAS 后端统一管理。
- 优先复用现有 Python 115 客户端。
- 不重复开发已有转存、目录浏览、文件查询、授权管理和播放地址解析能力。

### 5.2 115 账号管理

- 支持多账号；第一阶段可以只配置一个账号，但底层设计必须支持多个账号。
- 后端负责：账号授权、Cookie / Token 管理、授权状态、有效性检查、重新授权、账号切换、默认账号、账号对应的操作权限。
- iOS 不保存或直接管理 115 授权凭证。

### 5.3 网盘页面

底部导航中的「网盘」是完整网盘管理入口，负责：

- 文件和目录浏览。
- 文件搜索、文件排序。
- 文件播放入口。
- 多账号管理、账号切换、授权状态。
- 转存任务信息、转存成功和失败结果。
- 115 文件查询及相关管理操作。

网盘页面复用 Python 115 客户端能力。**不**将影视页面的网盘在线播放流程设计成跳转到网盘页面。

### 5.4 页面级转存目录配置

转存目录由用户配置，不自动创建影视目录。按发起操作的页面决定转存目标：

| 发起页面 | 转存目标 |
| --- | --- |
| 电影详情 | 电影配置目录 |
| 电视剧详情 | 电视剧配置目录 |
| 动漫详情 | 动漫配置目录 |
| 短剧详情 | 短剧配置目录 |
| 全局搜索 | 全局搜索默认目录 |

如果对应页面没有配置目录：

- 弹出 115 目录选择器。
- 用户选择本次目标目录。
- 本次选择只对本次转存生效，不自动修改默认配置。

同一组多条磁力链接多选转存时，共用本次目标目录。

## 六、播放系统

### 6.1 播放器定位

播放器是资源获取后的播放终端，重点不是极致影音规格，而是：

- HTTP 在线播放稳定。
- 115 网盘视频播放稳定。
- 常见视频格式兼容。
- 字幕格式兼容。
- 字幕插件能力。
- iOS 原生交互体验。

### 6.2 播放模式

**A. 网盘在线（重点业务流程）**

1. 用户点击「网盘在线」后立即进入播放器页面。
2. iOS 通知 NAS 后端发起转存。
3. NAS 调用 Python 115 客户端执行转存。
4. 后端持续查询转存状态。
5. 转存完成后解析 115 播放地址。
6. 后端向 iOS 返回播放准备状态。
7. 一旦播放地址可用，播放器立即加载并自动开始播放。

用户不需要进入 115 网盘页面。等待期间显示明确的准备状态，例如「正在准备播放」。

**B. 在线播放**

1. 用户点击在线播放。
2. 后端获取或解析来源播放地址。
3. iOS 播放器加载播放地址。
4. 直接从真实资源来源获取视频流，不经过 115 转存。

**C. 磁力链接播放**

- 磁力链接通常不是可直接播放的视频 HTTP 地址，后端可以尝试解析。
- 如果已有能力能够获取可播放地址，则允许直接播放。
- 如果不能：不开发复杂 BT 流媒体服务，提示用户使用网盘在线，转存到 115 后播放。

### 6.3 转存与播放任务解耦

转存任务由 NAS 后端独立执行，不依赖 iOS 是否处于前台。用户退出播放器时：

- 不取消转存。
- 后端继续执行。
- 保存任务状态。
- 保留转存结果。
- 避免重复提交同一播放请求。

用户稍后可以重新进入相关播放流程检查状态。

### 6.4 播放通知

不开发 APNs 远程推送。通知范围：

- App 前台：站内通知。
- App 后台：在系统允许的情况下使用本地通知。
- App 被彻底关闭或系统杀掉：不保证通知。
- 下次打开 App：同步后端任务结果。

只有播放地址真正准备完成，才提示用户可以播放；单纯转存成功但无法解析播放地址，不应提示为可播放。

### 6.5 播放会话

建议后端建立独立播放会话标识，关联：用户、资源、资源来源、115 账号、转存任务、播放地址解析任务、播放状态、播放进度。

- iOS 通过会话状态接口轮询后端。
- 轮询频率由后端策略或 API 返回的建议间隔控制。
- App 进入后台后合理降低请求频率，返回前台后恢复检查。
- 播放地址准备完成后停止轮询。

### 6.6 播放器基础能力

第一阶段需要：

- HTTP / HTTPS 播放。
- 115 播放。
- 常见视频容器与常见视频编码。
- 多音轨切换。
- 内嵌字幕、外挂字幕。
- 倍速、进度拖动、播放控制、常见手势。
- 播放历史、断点续播。
- iOS 原生画中画 PiP。

暂时不要求：Dolby Vision、Dolby Atmos、TrueHD、DTS-HD、PGS 等高规格字幕格式。

**播放内核**

- KSPlayer 可以作为候选内核进行评估，但尚未最终锁定。
- 技术选型必须核实：具体版本、许可证、依赖库许可证、iOS 系统兼容性、HTTP 播放稳定性、115 播放地址兼容性、PiP 能力、字幕能力、长期维护情况。
- 建议通过独立 `PlayerFacade` / `Player Adapter` 隔离业务与播放内核，不得让业务层直接依赖某一个播放器内核的内部实现。

### 6.7 播放偏好

暂不做：按视频记忆音轨、按视频记忆字幕、按视频记忆播放速度、全局音轨和字幕偏好记忆。用户可以在播放期间手动调整。

### 6.8 PiP 与 AirPlay

- **PiP**：第一阶段实现，使用 iOS 原生画中画能力，支持切换到系统画中画窗口与系统播放控制。
- **AirPlay**：第一阶段不实现，架构预留，后续根据播放器内核能力接入。

## 七、字幕系统

字幕是本项目的重要独立子系统，不将字幕业务完全绑定播放器。

### 7.1 总体结构

1. 字幕来源 Provider。
2. 字幕搜索调度。
3. 字幕匹配。
4. 字幕下载。
5. 字幕存储。
6. 字幕索引。
7. 字幕处理。
8. 播放器字幕加载与显示。

### 7.2 字幕来源

支持：视频内嵌字幕、iOS 本地文件字幕、在线字幕插件、HTTP / HTTPS 字幕 URL。

常见字幕格式：SRT、ASS、SSA、VTT。PGS 暂不作为第一阶段重点。

### 7.3 在线字幕搜索

- 多来源并发搜索，各字幕插件统一输出标准字幕结果。
- 统一展示：字幕名称、字幕语言、字幕格式、字幕来源、版本信息、匹配度、更新时间（来源提供时）。
- 多来源同时搜索、结果逐步返回、单来源失败不影响其他来源。
- 自动识别重复字幕。
- 支持单来源重试。

### 7.4 字幕自动匹配

根据当前影视作品信息和文件信息自动匹配，匹配条件：

- 影视标准名称、原名和别名。
- 年份、季数、集数。
- 视频文件名。
- 发布版本信息（来源提供时）。

自动推荐最准确的字幕，但用户仍可查看其他搜索结果。不使用复杂 AI 内容识别。

### 7.5 字幕下载和加载

1. 多来源并发搜索。
2. 展示统一字幕列表。
3. 用户选择单条字幕。
4. 下载该条字幕。
5. 下载完成后自动加载到当前播放器。
6. 自动切换至新字幕。

不支持一次批量下载多条字幕或自动批量下载全部结果。

### 7.6 字幕存储

采用 NAS 统一字幕库：

- 优先保存到 NAS。
- 支持 iPhone 当前播放会话临时缓存。
- 再次播放同一作品时优先检查 NAS，优先复用已有字幕。
- 支持后台自动清理。

字幕库组织维度：

| 类型 | 组织维度 |
| --- | --- |
| 电影 | 作品、年份 |
| 电视剧 | 作品、季、集 |
| 动漫 | 作品、季度、季、集 |

字幕元数据：语言、格式、来源、版本、下载时间。同一作品可以保存多语言和多个字幕版本。

常规与私密模式字幕数据完全隔离。不支持人工上传字幕，不提供 Web 字幕库管理页面。

### 7.7 字幕处理能力

第一阶段：字幕格式解析、字幕加载、字幕切换、字幕样式、字体大小、颜色、位置、背景、时间轴偏移、编码处理。

后续扩展：双语字幕、机器翻译、AI ASR、自动字幕生成、AI 时间轴校准。

第一阶段预留 Subtitle Service 接口，不实现 AI 翻译能力。

## 八、短剧系统

### 8.1 定位

短剧是底部独立入口，与普通影视内容分开管理。重点是通过插件接入不同短剧来源，实现浏览、详情和在线播放。

### 8.2 插件模式

- 短剧采用 HTTP 插件模式，插件由 NAS 后端管理。
- 插件通过统一 HTTP 接口提供：短剧列表、短剧详情、剧集信息、播放地址、其他来源扩展信息。
- 不同短剧来源转换成统一标准数据结构，iOS 不需要为每个来源单独修改代码。

### 8.3 播放

短剧复用主播放器，复用 HTTP 播放、播放控制、字幕系统、播放历史、播放进度。短剧支持独立私密模式。

## 九、私密模式与安全

### 9.1 适用范围

影视和短剧都支持私密模式。常规模式与私密模式是两套独立的内容展示及数据访问空间。

### 9.2 入口

采用隐藏式入口，不显示明显的「私密」文字。触发后进行身份验证。

### 9.3 验证机制

- Face ID。
- 独立数字密码。

优先使用 Face ID；Face ID 不可用或验证失败时，允许使用独立密码。

支持修改密码、重新设置 Face ID、自动退出。App 切换到后台或锁屏后自动退出私密模式。

### 9.4 数据隔离

以下数据必须区分常规和私密空间：

- 影视栏目配置。
- 私密内容。
- 收藏。
- 播放历史。
- 播放进度。
- 搜索历史。
- 字幕库。
- 相关缓存。

常规模式不能看到私密数据；私密模式退出后，相关内容立即不可见。

### 9.5 后端安全

- 私密模式不能只依靠隐藏按钮和 iOS 界面。
- 后端必须实施权限校验和数据隔离。
- 建议每个相关数据对象携带 `user_id`、`privacy_scope`、`resource_id` 或 `content_id`。
- 私密数据查询必须经过后端权限验证。
- 敏感凭证使用安全存储机制。
- Face ID 只是本地身份验证入口，不能代替后端授权。

## 十、收藏、历史和下载

### 10.1 收藏

- 只收藏影视作品，不收藏单条资源。
- 收藏功能放在「更多」的「常用功能」快捷入口中查看。
- 收藏后保存作品标识和元数据关联。
- 再次进入收藏作品时，可以重新搜索最新资源，不固定保存当时的资源链接。
- 常规收藏与私密收藏完全隔离。

### 10.2 播放历史

记录：影视作品、剧集、播放时间、播放位置、播放会话状态。

- 播放历史服务于断点续播，不建设复杂媒体库管理功能。
- 播放进度应精确关联到具体视频或剧集。
- 建议在实际开始播放后再记录有效播放历史，避免转存失败或播放准备失败的资源产生无效记录。

### 10.3 断点续播

再次播放同一资源时：检查已有播放进度 → 提示继续播放或从头播放 → 用户可以选择。

播放历史和播放进度保存在 NAS，支持多设备同步。

### 10.4 历史清理

支持删除单条历史、批量删除、清空历史、自动保留周期设置。自动保留周期的具体选项待设置设计阶段确定。

### 10.5 搜索历史

搜索历史不是核心数据，支持：

- 自动记录关键词、记录搜索时间。
- 点击历史重新搜索。
- 删除单条、清空历史。
- 定时自动清理。

不做关键词收藏和复杂统计。搜索历史保存在 NAS，支持多设备同步；常规和私密模式完全隔离。默认保留天数尚未最终确认。

### 10.6 下载能力

不支持 iOS App 本地视频下载，只支持 115 网盘离线下载及相关转存能力。

## 十一、更多与设置中心

「更多」采用 **iOS 原生风格的分组设置中心**，不是九宫格功能菜单，也不是把所有开关堆在一张长列表里。

结构形态固定为：浅灰页面背景 + 白色圆角分组面板 + 少量高频功能快捷入口 + 分组标题 + 二级页面承载复杂配置。

### 11.1 一级页信息架构

「更多」首页只展示分类入口，分组顺序固定，不自创顺序：

| 顺序 | 分组 | 页面入口 | 主要内容 |
| --- | --- | --- | --- |
| 1 | 服务状态 | NAS 服务 | NAS 连接、服务状态、账号信息（带「已连接」状态徽标） |
| 2 | 常用功能 | 我的收藏、播放历史、115 网盘、插件管理 | 高频业务快捷入口 |
| 3 | 播放与字幕 | 播放设置、字幕设置、音频设置 | 播放体验配置 |
| 4 | 外观与首页 | 外观与主题、首页栏目配置 | 界面个性化 |
| 5 | 资源与数据 | 资源搜索设置、元数据服务、缓存管理 | 资源搜索与数据服务 |
| 6 | 网盘与服务 | 115 账号管理、默认账号、转存目录、短剧服务 | 后端业务配置 |
| 7 | 插件管理 | 插件列表 | iOS 简化管理，Web 端完整管理 |

| 9 | 应用与支持 | 关于与版本、问题反馈、日志与诊断 | 应用维护 |

页面底部展示应用版本信息（`RexHub · Version x.y`）。

**入口形式规则**

- 第 2 组「常用功能」是**快捷入口**，使用横向图标 + 文字的快捷入口项，不是设置开关，也不重复出现在下面的设置分组里。
- 第 1 组「服务状态」是带状态徽标的面板卡，不是普通跳转行；点击进入账号与服务设置二级页。
- 其余分组使用标准设置行，右侧为箭头、状态值或开关。
- 单个分组条目超过 5 个时拆分为两张卡，不把长列表塞进一张卡。

### 11.2 分组内容定义

**播放与字幕**

- 播放设置：默认播放行为、默认倍速、手势、画中画。
- 字幕设置：字幕来源、默认样式、编码、时间轴偏移。
- 音频设置：音轨选择、音量与音频输出相关偏好。

**外观与首页**

- 外观与主题：浅色 / 深色 / 跟随系统。
- 首页栏目配置：栏目启用与排序、展示数量、卡片布局（对应 3.1 首页配置职责）。

**资源与数据**

- 资源搜索设置：搜索来源、默认排序、缓存与搜索策略。
- 元数据服务：元数据 Provider 状态与来源说明。
- 缓存管理：占用大小展示与清理。

**网盘与服务**

- 115 账号管理、默认账号、页面转存目录、短剧服务状态。
- 具体配置项随后端能力逐步开放。

**隐私与安全**

- 私密模式设置：Face ID、独立密码、自动退出、私密栏目配置。
- 危险操作（退出登录、清除全部数据）独立分组，并增加二次确认步骤。

**应用与支持**

- 关于与版本、问题反馈、日志与诊断。

### 11.3 二级页面规则

- 一级页只放分类入口，复杂配置进入二级页面，不在首页展开。
- 二级页面沿用同一套分组列表样式，不另起一套 UI 风格。
- 二级页使用系统导航栏（返回 + 居中标题），保留侧滑返回。
- 开关类设置即时生效，不需要额外「保存」按钮。
- 二级页条目顺序统一为：常用项 → 高级项 → 危险操作。
- 典型二级页：播放设置、字幕设置、资源搜索设置、私密模式设置。

### 11.4 视觉与组件要求

- 页面背景使用浅灰系统背景，分组容器使用白色圆角面板，主要依靠背景层次而非阴影区分层级。
- 页面左右留白、分组间距、面板圆角、行高、分割线、图标风格统一，具体数值见 [UI 视觉效果与质感规范](./ui-design-guidelines.md) 6.7。
- 不使用九宫格布局、不为每个设置项做独立大卡片、不大面积使用彩色渐变与玻璃效果。
- 设置项的标题、说明、状态与箭头严格对齐；辅助说明使用小字号与弱化颜色。
- 组件需统一抽象，后续新增设置项不重新设计 UI：更多首页、设置分类页、分组容器、标准设置行、开关行、带值行、跳转行、危险操作行、快捷入口组。

具体设置项目可根据实际功能实现情况逐步开放。

## 十二、插件体系

插件系统是项目的重要扩展能力，但不要求所有服务都强制插件化。

### 12.1 插件管理原则

- 插件运行在 NAS 后端。
- 插件由 Web 管理端完整管理，iOS 只提供简化管理入口。
- iOS 不执行插件代码。
- 插件通过明确的协议与后端通信，输出统一数据结构。
- 插件失败不应影响核心业务。

### 12.2 插件类型

| 类型 | 职责 |
| --- | --- |
| A. 影视元数据 Provider | 影视搜索、作品详情、海报、背景图、演员、简介、季和剧集信息及其他元数据；TMDB 可作为首个接入来源，其他 Metadata API 通过插件扩展 |
| B. HTTP 资源搜索插件 | 接入符合统一 HTTP 协议的外部资源搜索来源 |
| C. 短剧插件 | 短剧列表、详情、剧集和播放地址 |
| D. 在线字幕搜索插件 | 搜索和获取字幕，例如 OpenSubtitles、ASSRT 等类似来源 |
| E. 字幕处理插件 | 翻译、双语、AI 识别、时间轴校准等扩展接口；第一阶段暂不实现 AI 能力 |

### 12.3 非插件化的服务

PostgreSQL 资源数据库、CloudSaver、PanSou、现有 Python 115 客户端不强制插件化，由核心后端通过 Adapter 接入。

### 12.4 插件统一协议

每类插件具有明确的接口规范，至少包括：

- 插件 ID、插件名称、版本、插件类型。
- 配置 Schema、能力声明。
- 健康状态、错误信息、日志、API 版本。

资源搜索插件还需定义统一输入和输出协议。元数据插件、短剧插件和字幕插件分别定义自己的业务协议，不能强行使用一个过于宽泛的接口。

### 12.5 插件管理界面

**Web 管理端**：安装或添加插件、启用和停用、配置、更新、日志、调试、权限管理、运行状态。

**iOS**：查看插件列表与状态、常用配置、启用和停用（按权限允许）、查看日志摘要。

## 十三、用户与权限体系

### 13.1 第一阶段

## 十六、部署架构

### 16.1 部署方式

完全自托管。主要服务运行在 NAS Docker 环境，iOS App 通过网络连接 NAS 后端。

### 16.2 网络要求

支持局域网访问、远程访问、IPv6 网络访问（部署环境支持时）、HTTPS、服务端身份认证。

### 16.3 视频流量原则

NAS 主要提供：身份认证、配置服务、搜索调度、资源信息、115 授权和转存、播放地址解析、字幕服务。

视频数据原则上不经过 NAS 中转，iPhone 直接连接真实视频来源，以降低 NAS 的带宽、CPU 和存储压力。

## 十七、非功能要求

### 17.1 性能

- 首页栏目优先读取缓存。
- 海报异步加载。
- 多来源搜索并发执行。
- 搜索结果逐步返回。
- 单个来源失败不阻塞整体。
- 播放器进入页面不等待转存完成。
- 字幕搜索支持逐步返回。

### 17.2 稳定性

- 单来源异常不影响其他来源。
- 插件异常不能导致核心服务整体崩溃。
- 转存任务不能依赖 iOS 前台。
- 播放会话能够恢复。
- 搜索取消状态正确。
- 缓存异常不影响核心数据。

### 17.3 安全

- NAS API 必须认证。
- 115 授权信息仅在后端管理。
- 私密模式必须有服务端权限隔离。
- 插件必须有权限边界。
- 插件配置和密钥不能暴露给普通客户端。
- 视频地址和分享信息应按权限控制返回。

### 17.4 可维护性

- 核心业务与 Provider 解耦。
- 播放器与具体内核解耦。
- 资源来源与标准化模型解耦。
- 字幕搜索与字幕显示解耦。
- 插件协议版本化。
- 日志具备请求、搜索和播放会话关联标识。

## 二十一、项目最终原则

1. **产品定位不能偏离**：这是资源搜索、115 转存和在线播放工具，不是 Emby 式媒体库。
2. **搜索准确性第一**：不要为了搜索结果数量而引入无关内容。
3. **复用优先**：优先使用现有 Python 115 客户端和成熟服务，不重复实现已有功能。
4. **核心能力稳定**：影视发现、资源搜索、115 转存和播放必须形成稳定闭环。
5. **插件扩展有边界**：适合插件化的能力插件化，不适合的采用原生 Adapter。
6. **iOS 体验优先**：iOS 负责交互、展示和播放体验，NAS 负责服务端业务。
7. **视频流不经过 NAS**：除非特定来源或技术限制必须代理，否则优先直连真实视频来源。
8. **私密数据真正隔离**：不能只通过隐藏 UI 实现私密模式。
9. **不盲目堆功能**：优先完成核心业务，AI 字幕、AirPlay 等后续能力按阶段推进。
10. **架构可替换**：播放器、资源来源、元数据和字幕服务都应通过明确接口解耦。

最终产品体验：用户打开 iOS App，浏览影视海报，进入作品详情，找到准确的资源；需要网盘播放时，一键转存 115 并自动播放，需要直接播放时则直接加载来源视频。字幕服务可以自动寻找合适字幕，短剧和私密内容也有独立入口。

NAS 在后台负责所有复杂业务，用户在 iPhone 上只需要完成简单、连贯、稳定的操作。项目核心是让影视资源的发现、获取、转存和播放形成一条流畅的完整链路。
